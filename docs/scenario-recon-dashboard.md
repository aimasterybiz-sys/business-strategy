# 🟢 Финал занятия. Дашборд разведки (артефакт)

Развёрнутый сценарий к блоку «Дашборд разведки» из темы 3 «Отдел разведки».
Заменяет одноабзацный промпт в конце занятия.

🎯 **Что делаем:** собираем из материалов отдела «3. Отдел разведки» один
интерактивный HTML-дашборд, который дальше обновляется сам — еженедельной
автозадачей из Задания 8.

🏆 **Ценный результат:** файл «Дашборд разведки.html» в корне отдела. Открывается
двойным кликом, работает без интернета, показывает шесть блоков, и каждую неделю
в нём появляются новые сигналы без вашего участия.

⏱️ **Время:** 15 минут на занятии (шаги 1–2), автообновление — 🟡 после.

---

## Главная идея: данные отдельно, картинка отдельно

Обычный «сделай дашборд» даёт красивый, но мёртвый файл: через неделю данные
устарели, и агент пересобирает его заново — с нуля, другим по виду, с потерянной
историей.

Поэтому делим на два слоя:

| Слой | Файл | Кто меняет |
|---|---|---|
| **Данные** | `Дашборд — данные.json` | агент: при сборке и каждую неделю автозадачей |
| **Представление** | `Дашборд разведки.html` | человек: только когда меняется состав блоков |

HTML читает JSON, встроенный в него же (одним файлом, как требует занятие).
Автозадача дописывает JSON и пересобирает файл. История сигналов копится, а не
перезаписывается.

> Это тот же приём, что и в Excel-отчётах: таблицы данных отдельно, графики
> ссылаются на диапазоны. Правишь данные — картинка пересчитывается.

Три шага:

1. **Шаг 1** — контракт данных: агент вычитывает папки отдела и собирает JSON.
2. **Шаг 2** — оболочка: одностраничный HTML на шесть блоков.
3. **Шаг 3** 🟡 — автообновление: недельная автозадача дописывает и пересобирает.

## 🟢 Шаг 1. Промпт — собрать данные из папок отдела

Запускать **после** того, как в отделе есть хотя бы карта трендов, карта
конкурентов и один цифровой след. Пустые блоки — это нормально, дашборд их
покажет как «нет данных» с подсказкой, каким заданием закрыть.

```plain text
Собери данные для дашборда разведки из папок отдела «3. Отдел разведки».

Источники по блокам:
- тренды      → «Рынок и тренды» / «Карта трендов — [дата]»
- конкуренты  → «Конкуренты» / «Карта конкурентов», досье, «Позиционная матрица»
- гео         → «Конкуренты» / «Тепловая карта рынка»
- боли        → «Целевые аудитории и сегменты» / «Сегменты и карта болей»
- AI-видимость → «Диджитал-маркетинг» / «AI-видимость бренда»
- сигналы     → «Мониторинг и сигналы» / все файлы «Сигналы — [дата]»
- контр-офферы → файл «Маркетинг конкурентов — [дата]»; в занятии промпт
  Задания 5 сохраняет его в «Конкуренты», хотя заголовок задания указывает
  «Маркетинг» — ищи в обеих папках

Правила сборки:
1. Переноси только то, что реально есть в файлах. Ничего не додумывай:
   если поля нет — ставь null, а не правдоподобное значение.
2. У каждого факта сохраняй источник (ссылку), дату и метку достоверности
   из шкалы: confirmed / probable / rumor (✅ / ⚠️ / ❓).
3. У каждого блока сохраняй строку «что это значит для нас» — она уже
   есть в исходных файлах, её нельзя терять при переносе.
4. Сигналы складывай в один общий список по всем файлам «Сигналы — [дата]»,
   от новых к старым, без дублей.
5. В конце допиши раздел gaps: какие блоки остались пустыми и каким
   заданием занятия они закрываются.

Формат — строго такой JSON:

{
  "meta": { "company": "", "niche": "", "market": "", "built": "ГГГГ-ММ-ДД",
            "period": "ГГГГ-ММ … ГГГГ-ММ" },
  "trends": [ { "name": "", "horizon": "сейчас|6-12мес|дальний",
                "status": "использовать|готовиться|игнорировать",
                "driver": "", "demand_impact": "", "means_for_us": "",
                "example": "", "source": "", "date": "", "confidence": "" } ],
  "competitors": [ { "name": "", "site": "", "type": "прямой|непрямой|челленджер|заменитель",
                     "segment": "", "scale": null, "threat": "высокая|средняя|низкая",
                     "price_index": null, "quality_index": null,
                     "is_us": false, "was_unknown": false,
                     "source": "", "date": "", "confidence": "" } ],
  "geo": { "city": "", "points": [ { "name": "", "lat": null, "lon": null,
             "rating": null, "reviews": null, "price_level": null } ],
           "gaps": [ { "area": "", "why": "" } ] },
  "pains": [ { "pain": "", "segment": "", "frequency": null, "quote": "",
               "source": "", "date": "", "confidence": "" } ],
  "ai_visibility": [ { "brand": "", "is_us": false, "share_of_voice": null,
                       "mentions": null, "delta": null, "cited_pages": [],
                       "date": "", "confidence": "" } ],
  "signals": [ { "date": "", "competitor": "", "category": "цены|вакансии|запуск|отзывы|СМИ",
                 "signal": "", "means_for_us": "", "severity": "высокая|средняя|низкая",
                 "source": "", "confidence": "" } ],
  "gaps": [ { "block": "", "why_empty": "", "close_with": "Задание N" } ]
}

Сохрани файл «Дашборд — данные.json» в корень отдела «3. Отдел разведки».
В ответе покажи: сколько записей вышло по каждому блоку и какие блоки пустые.
```

**Зачем отдельный шаг.** Пока данные не выписаны в одну структуру, агент
на каждой пересборке заново читает десяток markdown-файлов и каждый раз
интерпретирует их чуть иначе. Контракт фиксирует смысл один раз.

## 🟢 Шаг 2. Промпт — собрать дашборд

```plain text
Собери интерактивный HTML-дашборд разведки из файла «Дашборд — данные.json».

ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ
- Один файл .html. Ни одного обращения в сеть: без CDN, без внешних шрифтов,
  без картинок по ссылке, без карт по API. Проверка — открыть с выключенным
  интернетом, всё должно работать.
- Данные вставь внутрь файла как <script type="application/json" id="recon-data">.
  Вся отрисовка читает только этот блок — никаких цифр, зашитых в разметку.
  Это условие пересборки: заменили JSON — дашборд показывает новое.
- Графики рисуй инлайновым SVG или canvas своими руками, без библиотек.
- Работает на телефоне: ничего не уезжает за правый край, широкие таблицы
  скроллятся внутри своего блока, а не тянут всю страницу.
- Светлая и тёмная тема.

ШАПКА
Слева — компания, ниша, рынок, период. Справа — дата последней сборки
и счётчик «новых сигналов с прошлой недели».
Строка из 4 плиток: конкурентов на радаре · трендов «использовать» ·
сигналов за 30 дней · наша доля голоса у AI (со стрелкой изменения).

ФИЛЬТРЫ — одной строкой над блоками, действуют на все блоки сразу:
- период: 30 / 90 дней / всё время
- конкурент: все / конкретный
- достоверность: ✅ только подтверждённое · ✅⚠️ · всё, включая ❓
По умолчанию — ✅⚠️. Слухи спрятаны, пока их явно не попросят.

ШЕСТЬ БЛОКОВ

1. Карта трендов — светофор.
   Три колонки по горизонтам («уже здесь» / «6–12 мес» / «дальний»),
   карточки трендов внутри. Цвет статуса: использовать / готовиться /
   игнорировать. Клик по карточке разворачивает: драйвер, влияние на спрос,
   «что это значит для нас», пример игрока, ссылка на источник.

2. Конкуренты — карта и позиционная матрица.
   Слева таблица: конкурент · тип · сегмент · угроза · был ли неизвестен нам.
   Сортировка по любому столбцу, поиск по названию.
   Справа bubble-матрица: X — цена, Y — класс/качество, размер пузыря —
   масштаб. Нас выделить отдельно — контуром и подписью, не только цветом.
   Наведение на пузырь подсвечивает строку в таблице, и наоборот.
   Тех, кого мы не знали до разведки, пометить бейджем «новый на радаре».

3. Тепловая карта рынка.
   Точки конкурентов по координатам из geo.points на схематичной сетке
   района, плотность — заливкой ячеек. Подложка карты не нужна: тайлы
   OpenStreetMap — это внешний запрос, а он запрещён. Полноценная
   Leaflet-карта остаётся отдельным файлом в папке «Конкуренты»,
   в дашборде даём на неё ссылку.
   Ячейки «белых пятен» подписать и вывести списком с выводом «почему здесь».

4. Карта болей клиентов.
   Горизонтальные полосы: боль × частота упоминаний, группировка по сегментам.
   Клик по полосе открывает цитаты клиентов с источником и датой.
   Рядом — колонка «наш контр-оффер» из файла «Маркетинг конкурентов», если он есть.

5. AI-доля голоса.
   Столбцы по брендам, наш выделен. У каждого — изменение к прошлому замеру
   со знаком (+/−). Ниже — страницы, которые AI цитирует чаще всего,
   и строка «по каким темам нас не видно».

6. Лента сигналов.
   Хронология от новых к старым: дата · конкурент · категория · сигнал ·
   «что это значит для нас» · источник. Сигналы, появившиеся после прошлой
   сборки, помечены как новые. Фильтр по категории. Кнопка «показать только
   высокую значимость».

ПРАВИЛА ОФОРМЛЕНИЯ
- Цвет кодирует сущность, а не порядковый номер: у конкурента свой цвет
  во всех блоках, и он не меняется, когда фильтр убирает других.
- Статусные цвета светофора (использовать / готовиться / игнорировать)
  зарезервированы под статус и больше нигде не используются.
- Достоверность показывается значком ✅ ⚠️ ❓ рядом с фактом, а не только
  цветом — иначе она пропадёт при печати и для дальтоников.
- У каждого факта видна ссылка на источник и дата. Факт без источника
  в дашборд не попадает.
- Пустой блок не прячем: показываем плашку «нет данных» и подсказку
  из gaps — каким заданием он закрывается.

Сохрани файл «Дашборд разведки.html» в корень отдела «3. Отдел разведки»
и покажи артефактом.
```

## 🟡 Шаг 3. Промпт — сделать дашборд самообновляемым

Запускать после Задания 8, когда еженедельная автозадача уже работает.

```plain text
Дополни еженедельную автозадачу мониторинга (понедельник, 9:00) третьим шагом.

Сейчас она: собирает сигналы → сохраняет «Сигналы — [дата]».
Добавь: после сохранения отчёта обнови дашборд.

1. Открой «Дашборд — данные.json».
2. Допиши новые сигналы в начало массива signals — старые не трогай
   и не перезаписывай, лента должна расти.
3. Обнови meta.built на сегодняшнюю дату.
4. Если в отчёте недели были изменения по конкурентам (новая цена, новый
   игрок, смена позиционирования) — поправь соответствующие записи
   в competitors и добавь дату изменения.
5. Пересобери «Дашборд разведки.html», подставив обновлённый JSON.
   Саму вёрстку и набор блоков не меняй — меняются только данные.
6. В отчёт недели добавь строку: «Дашборд обновлён, новых сигналов: N».

Если за неделю ничего нового — JSON и дашборд не трогай,
в отчёте одна строка «без изменений».
```

**Что после этого меняется.** Дашборд перестаёт быть снимком на дату занятия.
Открываете его в любой понедельник — сверху лента с пометкой, что появилось
за неделю, у AI-доли голоса стрелка изменения, у конкурентов актуальные цены.
Это и есть «цифровой двойник» из Задания 3, только по всему рынку сразу.

## Что здесь значит «интерактивный»

| Элемент | Что делает | Зачем |
|---|---|---|
| Фильтр достоверности | прячет ❓ слухи | решения принимаются только по ✅ |
| Фильтр по конкуренту | оставляет одного во всех шести блоках | собрать полную картину по игроку за один клик |
| Клик по карточке тренда | разворачивает «что это значит для нас» | вывод, а не факт |
| Связка таблица ↔ матрица | наведение подсвечивает в обе стороны | понять, кто этот пузырь |
| Клик по боли | открывает цитаты клиентов | проверить, что боль настоящая |
| Пометка «новое» | что появилось с прошлой сборки | не перечитывать всё заново |

Три вещи, которые чаще всего просят добавить, но не надо:
анимации переходов, «красивые» градиентные заливки на всё и счётчики,
которые крутятся при загрузке. Дашборд разведки читают по понедельникам
две минуты — всё, что мешает читать, вредит.

- [ ] Фильтр «только ✅» действительно убирает ⚠️ и ❓ из всех блоков.
- [ ] Мы выделены в матрице конкурентов и в AI-доле голоса — контуром или
      подписью, не только цветом.
- [ ] На телефоне страница не едет вбок.
- [ ] После прогона автозадачи дата сборки в шапке изменилась, а старые
      сигналы остались на месте.

## 🆘 Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| Дашборд пустой или в цифрах чушь | агент не нашёл файлы и додумал данные | проверить имена файлов; в промпте шага 1 есть прямой запрет додумывать — повторить его |
| Карта не рисуется | агент подтянул Leaflet с CDN | явно: «без внешних запросов, схематичная сетка вместо тайлов» |
| Через неделю дашборд «забыл» старые сигналы | автозадача пересобрала JSON с нуля | шаг 3, пункт 2: дописывать в начало массива, не перезаписывать |
| Каждая пересборка выглядит по-новому | вёрстка генерируется заново | в шаге 3 прямо сказано: менять только данные, вёрстку не трогать |
| Цвета конкурентов скачут при фильтре | цвет назначается по порядку в отфильтрованном списке | цвет закрепить за именем конкурента один раз |
| Файл весит десятки мегабайт | агент вшил картинки в base64 | картинки в дашборде не нужны — только SVG-графики |

## 🟡 Расширения

- **Диффы недели.** Отдельный блок «что изменилось»: цены вверх/вниз,
  новые вакансии, новые игроки — только дельта, без общей картины.
- **Экспорт в PDF** одной кнопкой (`window.print()` + печатные стили) —
  чтобы дашборд уходил в совет директоров как есть.
- **Сентимент-дельта** из шпаргалки занятия: график изменения тональности
  неделя к неделе как ранний сигнал.
- **Связь со стратегией.** Блоки дашборда — это вход в SWOT и Портера
  на теме по AI-стратегии: тренды → возможности, боли → угрозы и офферы,
  матрица → конкурентная позиция.

## Промпт создания скилла «Дашборд разведки»

Создавать после того, как пересобрали дашборд 2–3 раза и формат устоялся.

```plain text
Создай скилл «Дашборд разведки».
Назначение: пересобирать интерактивный дашборд отдела разведки
из материалов папок, не меняя вёрстку между запусками.
Запуск фразами: «собери дашборд разведки», «обнови дашборд».

Что делает скилл при запуске:
1. Читает папки отдела «3. Отдел разведки» и обновляет файл
   «Дашборд — данные.json» по фиксированной схеме: meta, trends,
   competitors, geo, pains, ai_visibility, signals, gaps.
   Ничего не додумывает: нет данных — null. Сигналы дописывает
   к существующим, не перезаписывает.
2. Каждый факт переносит вместе с источником, датой и меткой
   достоверности (подтверждён / вероятен / слух) и со строкой
   «что это значит для нас».
3. Пересобирает «Дашборд разведки.html»: один файл, без внешних
   запросов, данные внутри как JSON-блок, шесть блоков — светофор
   трендов, конкуренты и bubble-матрица, тепловая карта, карта болей,
   AI-доля голоса, лента сигналов. Фильтры: период, конкурент,
   достоверность.
4. Вёрстку между запусками не меняет — меняются только данные.
5. Сохраняет оба файла в корень отдела и отвечает сводкой:
   что обновилось, сколько новых сигналов, какие блоки пустые.

Возьми за образец мой текущий «Дашборд разведки.html».
Оформи как файл скилла, который я добавлю
через Настройки → Возможности → Скиллы.
```

## Куда это встаёт в занятии

В «Порядке работы участника» пункт 8 сейчас звучит как «Финал: сверка отдела +
дашборд из собранного». Разворачивается в:

8. 🟡 Финал: сверка отдела (пустые папки — осознанно или пробел) →
   **шаг 1: контракт данных** → **шаг 2: сборка дашборда** (🟢, 15 минут) →
   **шаг 3: автообновление** (🟡, после Задания 8).

Дашборд собирается уже на занятии — по тем данным, что есть. Пустые блоки
честно показывают, что не сделано, и это работает лучше списка «Пробелы»:
дырку в дашборде видно сразу.
