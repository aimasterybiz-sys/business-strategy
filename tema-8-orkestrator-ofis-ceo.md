# Тема 8. Оркестратор «Офиса CEO» — Агент 008 «Стратег»

Предложение: какого агента-оркестратора сделать в теме 8 легко и быстро,
из уже построенных агентов тем 1–7, и что он будет делать.

**Ключевая рамка.** На занятии темы 8 работает **приложение по всем
стратегическим вопросам** (7-этапный маршрут, SWOT/TOWS, Портер, голубой
океан, Румельт, каскад выборов, пре-мортем, «убей компанию» и остальные
методики — с графиками и автоматическим разбором). Методики — территория
приложения. **Оркестратор приложение не дублирует**: ни одну методику
не проводит, ни одного графика не строит, ни одного разбора не пишет.
Его территория — **до** приложения и **после** него.

---

## Краткий вывод

Оркестратор темы 8 — **«Стратег» (Агент 008, Офис CEO)**: штабной агент
вокруг стратегического приложения. Один SKILL.md через skill-creator —
по той же схеме, по которой участники уже дважды собирали оркестраторы
(«Плановое обслуживание» в теме 1, оркестратор студии в теме 4).

Делает ровно две вещи, которые приложение сделать не может, потому что
не видит базу знаний и AI-команду:

1. **ДО приложения — «Стратегический паспорт»**: собирает из папок
   отделов 1–6 готовые данные для ввода в приложение, разложенные
   по его этапам, каждый факт со ссылкой на файл-источник. Отдельно —
   «Пробелы стратегии»: чего в базе нет и кто из агентов может добрать.
2. **ПОСЛЕ приложения — внедрение**: принимает итог стратегической
   сессии в папку «8. Офис CEO», прогоняет ведомственную проверку
   реализуемости силами существующих агентов (юрист, финансист)
   и каскадирует: поручения — секретарю в доску, индикаторы —
   разведчику в «Сигналы», контент-план — студии, пороги — финансисту.
   Ведёт «Журнал решений» и квартальный ритм ревью.

Во время работы в приложении Стратег молчит и подключается только
по запросу — как справочная: «что у нас по…» → ответ из базы со ссылкой
(это вызов агента знаний, не собственный анализ).

Оценка трудоёмкости на занятии: **~30 минут** (один промт в skill-creator,
один промт в кабинет директора, тестовый прогон паспорта).

## Разделение труда: приложение vs Стратег

| Вопрос | Приложение | Стратег |
|---|---|---|
| Проведение методик (SWOT, Портер, океан, пре-мортем…) | ✅ да, с графиками и разбором | ⛔ никогда |
| Откуда данные для методик | владелец вводит | готовит паспорт: данные для ввода, по этапам приложения, с источниками |
| Ответ на вопрос «а какая у нас маржа / кто конкурент №2?» | не знает — нет доступа к базе | отвечает из базы со ссылкой (через агента знаний) |
| Проверка стратегии на реализуемость по базе компании | не может — не видит договоры и цифры | red-team юриста и финансиста по материалам базы |
| Что происходит с готовой стратегией | остаётся в приложении / экспорт | принимает в «8. Офис CEO», каскадирует по отделам, ведёт журнал и ритм |

Граница простая: **всё, где думают над методикой, — приложение; всё, где
нужны папки базы и агенты команды, — Стратег.** Пересечений нет.

## Почему именно такой оркестратор

1. **Данные готовы, но разбросаны.** Темы 1–6 наполнили общую базу; тема 3
   прямо обещает: «материалы отдела разведки станут входными данными для
   работы CEO». Без паспорта владелец будет заполнять приложение по памяти —
   и вся ценность шести занятий останется в папках.
2. **Внедрение — главная смерть стратегий.** Приложение заканчивается
   готовой стратегией; без каскадирования она остаётся документом «на
   полке». А канал исполнения уже построен: доска поручений секретаря
   (тема 2), еженедельные «Сигналы» разведчика (тема 3), оркестратор
   студии (тема 4), пороги финансиста (тема 5).
3. **Папка «8. Офис CEO»** (Стратегия · OKR и KPI · Журнал решений ·
   Отчётность) заложена в структуру базы ещё на первом занятии и до
   восьмого стоит пустой.
4. **Паттерн знаком.** Участники собирают оркестратор в третий раз
   и знают правила: один агент — одна роль; гейты не пропускать;
   за человека не отвечать.

## Что делает Стратег — три фазы

### Фаза 1 — ДО: «Стратегический паспорт» (главная работа)

Проходит по папкам отделов 0–6 и собирает один файл-пакет для ввода
в приложение, **разложенный по этапам приложения**, чтобы владелец
копировал блоками, а не искал по папкам:

- профиль бизнеса и цифры — из «0. О компании» и юнит-экономики финансиста;
- рынок, тренды, конкуренты — из Карты трендов, Карты конкурентов и досье
  разведчика (готовые входы для SWOT-возможностей/угроз и Портера);
- клиент и позиционирование — из Аватара, Сегментов, Оффера, Возражений
  продавца (входы для «где играем / как выигрываем», JTBD);
- бренд и голос — из БИЗНЕС.md студии;
- ограничения — красные линии из ФАКТЫ.md, правовые позиции юриста,
  финансовые пороги финансиста.

Каждый факт — со ссылкой на файл-источник и датой (стандарт базы с темы 1).
Устаревшее (старше квартала) помечает и предлагает обновить силами
профильного агента — сам не обновляет и не сочиняет.

Отдельным файлом — **«Пробелы стратегии»**: чего в базе нет, насколько это
критично для сессии и кто может добрать (разведчик / финансист / владелец).

**Гейт:** «паспорт готов, вот пробелы — идём в приложение или сначала
дособрать?»

### Фаза 2 — ВО ВРЕМЯ: справочная по запросу

Пока владелец работает в приложении, Стратег не вмешивается. Одна услуга:
на вопрос «что у нас по X?» отвечает из базы со ссылкой — это вызов агента
знаний, не собственный анализ. Методики, оценки, выборы — целиком
в приложении.

### Фаза 3 — ПОСЛЕ: внедрение

1. **Принимает итог сессии** (экспорт/выгрузку из приложения) и оформляет
   в «8. Офис CEO»: `Стратегия.md`, `OKR и KPI.md`, `Дорожная карта.md`,
   `Журнал решений` (дата · что решили · почему · кто).
2. **Проверка реализуемости по базе** — то, чего приложение сделать
   не может: ai-lawyer смотрит план через договоры и правовые позиции
   компании, fin-red-team — через реальные цифры и пороги. Это не повтор
   пре-мортема из приложения (тот работает с введёнными владельцем
   данными), а сверка с документами компании. Свод — таблица
   «ограничение → что меняем». **Гейт:** владелец решает по каждому пункту.
3. **Каскадирует:**
   - поручения с владельцами и сроками → секретарю в доску «Поручения»
     (дата проверки = контрольная точка дорожной карты);
   - индикаторы раннего предупреждения из сценариев → разведчику
     в регламент еженедельных «Сигналов»;
   - контент-план по стратегии → оркестратору студии;
   - финансовые пороги и красные линии → финансисту в «Правила и пороги».
4. **Ритм:** предлагает (не создаёт без «да») автозадачу «стратегическое
   ревью» раз в квартал: факт KPI против плана, свежие «Сигналы»,
   просроченные поручения → что меняем; итог — строкой в «Журнал решений».
   Перед следующей сессией в приложении паспорт пересобирается одной
   командой — данные всегда свежие.

## Чего Стратег НЕ делает (граница с приложением)

- не проводит ни одну методику: SWOT, Портер, океан, Румельт, каскад
  выборов, пре-мортем, «убей компанию» — только приложение;
- не строит графики и не пишет автоматические разборы — они у приложения;
- не пересчитывает и не «улучшает» результаты приложения;
- не принимает решений за владельца: готовит данные и последствия,
  выбор — человек;
- не пишет в чужие папки — только «8. Офис CEO».

## Драматургия занятия

Получается чистая тройка: **Стратег собирает паспорт → владелец проводит
сессию в приложении → Стратег внедряет результат через AI-команду.**
Приложение показывает силу методик, оркестратор — силу построенной за семь
занятий команды: разведчик принёс рынок, финансист — цифры, продавец —
клиента, юрист проверил реализуемость, секретарь взял исполнение на доску,
кабинет дал кнопку. Стратегия перестаёт быть документом «на полке»:
у неё есть журнал решений, квартальный ритм и индикаторы под мониторингом.
